# starry-parser — 语法分析模块

starry-parser 是一个自包含的语法分析库，实现了上下文无关文法的多种分析算法，覆盖从文法定义、文法变换、集合计算到自顶向下与自底向上解析的完整流程，最终输出抽象语法树（AST）。

## 核心概念与模块关系

### 第一层：文法基础设施

`cfg.rs` 定义了整个库的基石——**上下文无关文法（CFG）**。核心数据结构包括：

- **非终结符**：文法中的语法变量，可被展开为符号串
- **终结符**：文法中的基本符号，不可再分，对应源代码中的实际词法单元
- **产生式**：描述一个非终结符如何推导为终结符和非终结符的序列，形如 `左部 → 右部`。产生式是语法分析的原子规则
- **开始符号**：文法推导的起点，所有合法句子的推导都从开始符号出发

一个上下文无关文法定义了语言的语法结构，它的核心操作包括：解析文法字符串、按非终结符分组检索产生式、判定产生式是否为 ε 产生式。

### 第二层：共享工具层

`token_mapper.rs` 是 LL(1) 和 LR 模块共用的词法符号到终结符的映射逻辑。它将外部 Token（如整数、标识符、运算符等）映射到文法内部定义的终结符 ID，并提供终结符匹配的统一判定。

`ast_builder.rs` 实现从产生式规约结果到抽象语法树（AST）的构造。核心函数分析产生式的右部模式：

- **单符号右部**：直接透传子节点
- **中缀二元表达式**：识别非终结符—终结符—非终结符模式，构造二元运算 AST 节点
- **尾递归产生式**：识别尾部递归非终结符（如 `E → T + E`），用继承属性传递累积结果，避免深层嵌套
- **括号表达式**：识别 `( E )` 模式，构造括号 AST 节点
- **一元前缀表达式**：识别终结符—非终结符模式，构造一元运算 AST 节点

`parser.rs` 提供了基础的自顶向下递归下降分析器。它尝试匹配所有候选产生式，失败时回溯到保存的状态，最终生成语法分析树（Parse Tree）。语法分析树中的节点类型分为非终结符节点（包含子节点）和终结符节点（对应词法单元），以及表示空推导的 ε 节点。

### 第三层：文法分析工具集（analysis/）

#### FIRST 集 & NULLABLE 集

FIRST 集和 NULLABLE 集是几乎所有语法分析算法的基础。

**NULLABLE 集** 定义了一个非终结符是否可以推导出空串 ε。判定规则：如果非终结符有 ε 产生式，或有一个产生式的右部全部由 NULLABLE 符号组成，则该非终结符是 NULLABLE。计算采用不动点迭代：反复扫描产生式，直到没有新的 NULLABLE 符号被发现。

**FIRST 集** 定义了一个非终结符经过若干步推导后，所有可能出现在**句型最左端**的终结符集合。如果该非终结符是 NULLABLE，FIRST 集中还包含 ε。计算同样通过不动点迭代：对每个产生式 `A → X₁X₂...Xₙ`，从左到右扫描右部符号；将 FIRST(X₁) − {ε} 加入 FIRST(A)；如果 X₁ 是 NULLABLE，继续加入 FIRST(X₂) − {ε}，以此类推；如果所有右部符号都是 NULLABLE，将 ε 加入 FIRST(A)。

另外，还需要计算**符号串的 FIRST 集**——对于非单一符号的序列（如产生式右部），FIRST 集的传播规则同上。

#### FOLLOW 集

**FOLLOW 集** 定义了一个非终结符在所有句型中，紧跟在它**后面**的所有终结符集合。FOLLOW 集是 SLR(1) 分析器减少冲突和 LL(1) 预测分析表构造的关键。

计算规则基于三条：
1. 将结束标记 `$` 放入开始符号的 FOLLOW 集
2. 对产生式 `A → αBβ`，将 FIRST(β) − {ε} 加入 FOLLOW(B)
3. 对产生式 `A → αB` 或 `A → αBβ` 且 β 可为空时，将 FOLLOW(A) 加入 FOLLOW(B)

FOLLOW 集同样是固定点迭代计算。

#### 左递归检测与消除

**左递归** 是指一个非终结符在某些推导路径上，它的产生式右部第一个符号直接或间接地等于它自身。左递归分为：

- **直接左递归**：`A → Aα | β`，右部第一个符号就是 A
- **间接左递归**：`A → Bβ`，`B → Aγ`，经过若干步推导后形成环

直接左递归会导致自顶向下分析器（LL(1)）无限递归。左递归检测模块通过构建非终结符依赖图（基于每个产生式右部第一个符号），使用深度优先搜索（DFS）检测图中的环，从而发现直接和间接左递归。

左递归消除遵循龙书标准算法：先将非终结符排序，从前往后消除间接左递归（用低编号产生式的右部替换高编号产生式中以低编号符号开头的部分），再对每个非终结符消除直接左递归（通过引入新的辅助非终结符 A'，将 `A → Aα | β` 变换为 `A → βA'`，`A' → αA' | ε`）。

#### 短语、直接短语与句柄

在语法分析树的上下文中：

- **句型**（Sentential Form）：从开始符号可以推导出的任意终结符和非终结符的序列。在语法分析树中对应所有叶子节点从左到右构成的符号串。
- **短语**：语法分析树中以某个非终结符为根的子树对应的叶子节点序列。它表明该子串在文法中可归约为该非终结符。
- **直接短语**：子树深度为一的短语，即子树仅包含终结符叶子节点（或 ε）。直接短语对应的是语法分析树中"一步归约"的子结构。
- **句柄**（Handle）：当前句型中最左边的直接短语。在自底向上分析中，句柄就是当前应该归约的子串。句柄具有"最左"特性——任何归约动作必须在句柄处执行。

短语分析模块的工作流程：遍历语法分析树，为每个非终结符节点找到匹配的产生式，记录其叶子节点的起止范围。直接短语通过限制子树深度为 1 来筛选。句柄则取所有直接短语中叶子起始位置最小者。

句柄归约器实现了自底向上的归约过程：从最左边的句柄开始，逐步用产生式左部替换右部，直到整棵树归约为开始符号。归约过程可输出步骤跟踪，展示每一步归约的句柄和归约后的符号。

这套短语—直接短语—句柄的概念体系与 LR 自底向上分析中的"移进-归约"过程完全对应：**移进**将输入符号压栈，**归约**识别句柄并将右部符号替换为左部非终结符。

### 第四层：LL(1) 自顶向下分析（ll1/）

LL(1) 分析是一种**预测性自顶向下**的分析方法。它的名字含义是：**L**（从左到右扫描输入）、**L**（产生最左推导）、**(1)**（向前看一个符号）。

#### LL(1) 预测分析表

LL(1) 分析依赖于**预测分析表**。预测分析表是一个二维表，行为非终结符，列为终结符（包括结束标记 `$`），每个表项指示当栈顶为非终结符且当前输入为某终结符时应使用的产生式。

构造算法：
1. 对每条产生式 `A → α`，计算 FIRST(α)
2. 对 FIRST(α) 中的每个终结符 a，将产生式填入 M[A, a]
3. 如果 ε ∈ FIRST(α)，对 FOLLOW(A) 中的每个终结符 b，将产生式填入 M[A, b]
4. 如果出现冲突（同一表项有多个产生式），该文法不是 LL(1)

#### LL(1) 预测分析器（栈驱动）

LL(1) 预测分析器使用显式分析栈执行分析：

1. 初始化：将结束标记 `$` 和开始符号压入分析栈
2. 循环比较栈顶与当前输入符号：
   - 如果栈顶与输入都是 `$`，接受
   - 如果栈顶是终结符且匹配当前输入，消去栈顶并消耗输入符号
   - 如果栈顶是非终结符，查预测分析表获取产生式，将栈顶替换为产生式右部（反向压栈）
   - 如果查表失败，报错
3. 归约 AST 时，使用帧栈记录每次展开的语义动作位置

每一步展开时，展开前压入帧标记（记录当前 AST 栈深度），展开并匹配完成后弹出帧标记，取出帧内子节点，调用 AST 构建器归约为一个非终结符节点。

#### LL(1) 递归下降分析器

递归下降是 LL(1) 分析的另一种等价的实现方式——它将文法中的每个非终结符映射为一个递归函数：

1. 从开始符号对应的函数入口
2. 每个函数查看当前输入符号，查到预测分析表决定使用哪条产生式
3. 依次调用产生式右部每个符号对应的处理函数：终结符则匹配并消耗输入，非终结符则递归调用
4. 对于尾递归产生式（如 `E → T + E` 或 `E' → + T E'`），使用**继承属性**传递累积的 AST 子结构，将递归转换为迭代语义

递归下降的优势在于直观和易于调试，本质是将预测分析表的查表逻辑展开到函数的控制流中。

#### LL(1) 文法验证

LL(1) 验证器检查文法是否能构造出无冲突的预测分析表。若存在同一个非终结符面对同一终结符有多个候选产生式的情况，则文法不是 LL(1)。验证报告会列出具体冲突的 M[A, a] 表项。

### 第五层：LR 自底向上分析（lr/）

LR 分析是一类强大的**自底向上**分析方法，能处理比 LL(1) 更广的文法类别。其名字含义与 LL 类似：**L**（从左到右扫描）、**R**（产生最右推导的逆过程）。四种 LR 变体的能力呈包含关系：

```
LR(0) ⊂ SLR(1) ⊂ LALR(1) ⊂ LR(1)
```

#### 增广文法

增广文法是 LR 分析的起点。它在原始文法上添加一条新的产生式 `S' → S`，其中 S' 是一个全新的非终结符。这条产生式为 LR 分析器提供了"接受"的判定依据：当归约到 S' → S· 时，分析成功结束。这种设计统一了接受条件——不必为每种文法单独处理结束逻辑。

`S'` 的命名采用自动冲突避免策略：如果原文法已存在 `S'`，则尝试 `S'1`、`S'2` 等。

#### LR 项与项集

**LR(0) 项** 是产生式加上一个圆点位置。圆点表示"已经看到了多少"。形式上写作 `[A → α·β]`，含义是：期望从输入中看到一个可归约为 αβ 的子串，且已经识别了 α。当圆点到达产生式末尾（`[A → αβ·]`）时，表示该项可以执行归约。

**LR(1) 项** 在 LR(0) 项的基础上添加了**向前看符号**（lookahead），写作 `[A → α·β, a]`，含义是：在识别了 α 后，只有当前输入为 a（或 a 可以合法跟随）时，才能按照该产生式归约。向前看符号使分析器在做归约决策时更加精确，从而处理更复杂的文法。

**核项**（Kernel Item）特指圆点不在位置 0 的项以及增广文法的初始项。核项是项集的核心标识——两个项集如果核项相同，则它们**同心**。同心集合并是 LALR(1) 的核心操作。

**项集** 是一个状态的完整描述——在自动机的某个状态下，所有与分析相关的项。项集通过闭包运算和 GOTO 运算扩展到完整状态。

#### LR 闭包与 GOTO

**LR(0) 闭包** 计算：对项集中的每个 `[A → α·Bβ]`，将所有 `B → γ` 的初始项（圆点在 0）`[B → ·γ]` 加入项集，重复直到稳定。这是对"如果我们期望看到 B，那么 B 的任何产生式都可能是接下来要分析的"这一直观原理的数学化。

**LR(1) 闭包** 在 LR(0) 闭包的基础上进一步计算向前看符号：对于 `[A → α·Bβ, a]`，新的向前看符号 b 取自 FIRST(βa)。这确保了只有实际可能出现在跟随位置的终结符才被加入向前看符号。

**GOTO 函数** 定义状态转移：对于项集 `I` 和文法符号 `X`，GOTO(I, X) 选取所有圆点后为 X 的项，将圆点后移一位，再计算闭包。这构成了 LR 自动机的状态转移函数。

#### 自动机构造（项集族）

LR(0) 和 LR(1) 项集族构造遵循相同的算法框架（类似于 NFA 转 DFA 的子集构造）：

1. 从初始项集的闭包开始，作为状态 0
2. 维护一个工作列表，对每个未处理的状态：
   - 收集该状态中所有圆点后可能出现的符号
   - 对每个符号，计算 GOTO 函数得到新状态
   - 如果新状态已存在（项集相等），仅添加转移边
   - 如果新状态不存在，分配新的状态编号，加入工作列表
3. 工作列表为空时，自动机构造完毕

LR(0) 自动机约有数十个状态（对中等复杂文法），LR(1) 自动机的状态数通常是 LR(0) 的数十倍甚至更多——因为向前看符号的不同组合导致相同的 LR(0) 核心分裂为多个状态。

#### 四种 LR 分析表构造

##### LR(0) 分析表

LR(0) 最简单也最受限。在 LR(0) 自动机上：
- 对 `[A → α·aβ]`，在 ACTION 表中填入移进到 GOTO(I, a)
- 对 `[A → α·]`，在 ACTION 表的**所有**终结符上填入归约
- 对 `[S' → S·]`，在结束标记 `$` 上填入接受

LR(0) 不考虑向前看，任何一个归约项对所有终结符都执行归约，因此冲突频繁。只有当移进项和归约项不在同一终结符上出现时，文法才是 LR(0)。

##### SLR(1) 分析表

SLR(1)（Simple LR）在 LR(0) 自动机的基础上引入 FOLLOW 集来减少冲突：
- 归约 `[A → α·]` 不再对所有终结符归约，而是仅在 FOLLOW(A) 中的终结符上归约
- 这避免了 FOLLOW 集外的终结符上产生移进—归约冲突

SLR(1) 利用 LR(0) 自动机的简洁性，同时通过 FOLLOW 集提供有限的上下文区分。它比 LR(0) 强大，但不如 LR(1) 精确——因为 FOLLOW 集是对整个文法的全局分析，而 LR(1) 的向前看是状态局部的。

在构造过程中，如果原 LR(0) 表有冲突但 SLR 后消除了，这些冲突会被记录为"已解决的冲突"。

##### LR(1) 分析表

LR(1)（Canonical LR）是最精确的 LR 变体。它在 LR(1) 自动机上：
- 移进规则与 LR(0) 相同
- 归约仅在特定向前看符号上执行（由 LR(1) 项携带的 lookahead 决定）

LR(1) 被接受为规范 LR，因为它完全不给"可能有冲突"留任何余地。代价是状态数的指数级暴增——这是 LR(1) 在实际实现中很少被直接使用的原因。

冲突检测通过收集每个状态中的所有移进符号和归约符号，检查交集来判定。

##### LALR(1) 分析表

LALR(1)（Look-Ahead LR）是实用价值最高的 LR 变体——它在保持 LR(0) 级别状态数的同时，几乎拥有 LR(1) 的精确度。

构造流程：
1. 先构造完整的 LR(1) 自动机
2. 识别**同心集**（具有相同核项的 LR(1) 项集）
3. 将同心集合并，把它们的向前看符号做并集
4. 在合并后的状态上构造分析表

核心数据结构 `CoreSetMerger`（同心集合并器）维护一个从核项到状态编号的映射。每次向合并器添加一个 LR(1) 项集时：如果核项已存在，将向前看符号合并进去；如果核项不存在，创建新状态。这种增量合并保证了正确性。

LALR(1) 合并后可能引入新的归约—归约冲突（因为原本在不同状态下分开的归约项合并后共用同一个 ACTION 表行），但不会引入新的移进—归约冲突。这是 LALR(1) 的理论保证。

#### LR 分析器运行逻辑

LR 分析器的核心流程是一个**移进-归约**循环：

1. **初始化**：状态栈压入状态 0，输入指针指向第一个符号，AST 栈为空
2. **循环**，根据当前栈顶状态和当前输入符号查 ACTION 表：
   - **移进（Shift s）**：将当前输入符号作为叶子 AST 节点压入 AST 栈，将终结符和状态 s 压入状态栈，输入指针前进
   - **归约（Reduce r）**：弹出的栈符号数等于产生式右部长度乘以 2（每个文法符号后跟一个状态），从 AST 栈取出相应数量的子节点，调用 AST 构建器归约为非终结符节点压回；然后查 GOTO 表决定压入的新状态
   - **接受（Accept）**：出现在将 `S' → S` 归约且当前输入为 `$` 时，分析成功结束，根 AST 节点即为结果
   - **错误（Error）**：无合法动作，可选地触发错误恢复（跳过当前输入符号继续尝试）
3. **跟踪输出**：可选地记录每一步的栈状态、输入状态和动作，生成完整的分析跟踪（ParseTrace）

状态栈采用交替存储模式：每两个元素一组，第一个是文法符号，第二个是状态。栈顶始终是当前状态。

#### LR 文法类型判定

`LRValidator` 和 `builder.rs` 中的 `LRValidator` 实现了文法类型的自动判定：

1. 构造 LR(0) 项集族和 SLR 表
2. 如果 SLR 表无冲突，检查是否 LR(0)（原始 LR(0) 表也无冲突，即没有移进—归约冲突需要 FOLLOW 集解决）还是 SLR(1)
3. 如果 SLR 表有冲突，尝试 LR(1) 和 LALR(1)
4. 返回最高的文法类型

结合 `LRParserBuilder`，用户可以指定期望的文法类型（如 LALR1），构建器会自动构造对应的分析表并检测冲突。如果文法不满足指定类型，返回详细的冲突报告。

### 两条完整执行路径

#### 路径一：LL(1) 自顶向下分析（demo_parser.rs）

1. 解析文法字符串 → `ContextFreeGrammar`
2. 检测左递归 → 若存在，执行左递归消除（引入 E'、T' 等辅助非终结符）
3. 计算 NULLABLE 集、FIRST 集、FOLLOW 集
4. 构建 LL(1) 预测分析表 → 检查冲突
5. 将 Token 流输入 LL(1) 预测分析器或递归下降分析器
6. 分析过程中，查预测分析表决定展开/匹配，同时用帧栈管理 AST 语义归约
7. 输出抽象语法树

#### 路径二：LR 自底向上分析（demo_parser_lr.rs）

1. 解析文法字符串 → `ContextFreeGrammar`
2. 构造增广文法（添加 S' → S）
3. 展示全部 LR(0) 和 LR(1) 项（枚举所有可能的圆点位置 × 向前看符号组合）
4. 构造 LR(0) 项集族 → 构造 LR(0) 分析表 → 判定是否为 LR(0)
5. 计算 FIRST 集、NULLABLE 集、FOLLOW 集
6. 构造 SLR(1) 分析表 → 判定是否为 SLR(1)
7. 构造 LR(1) 项集族 → 构造 LR(1) 分析表 → 判定是否为 LR(1)
8. 对 LR(1) 项集族执行同心集合并 → 构造 LALR(1) 分析表 → 判定是否为 LALR(1)
9. 选择 LALR(1) 分析器，对 Token 流执行移进-归约循环
10. 输出分析跟踪和抽象语法树

### 文法类型的包含关系与能力边界

| 文法类型   | 向前看策略          | 状态数  | 判定能力                     | 实际应用           |
|-----------|--------------------|---------|-----------------------------|-------------------|
| LR(0)     | 无需向前看          | 最少    | 极少数文法（如简单表达式）    | 仅教学意义         |
| SLR(1)    | 全局 FOLLOW 集      | 同 LR(0)| 多数无二义文法               | 分析器自动生成入门  |
| LALR(1)   | 状态局部的向前看合并 | 同 LR(0)| 几乎所有程序设计语言文法      | Yacc/Bison/实际工程 |
| LR(1)     | 状态局部的精确向前看 | 最多    | 所有确定性上下文无关语言       | 理论基准           |
| LL(1)     | 自顶向下查表        | N/A     | 无左递归、无公共前缀文法      | 手写递归下降分析器  |

**LL(1) 与 LR 的关系**：LL(1) 不是 LR(1) 的子集，LR(1) 也不是 LL(1) 的超集。它们是两类不同的分析方法，各有适用场景。LL(1) 最适合手工编写递归下降分析器；LR 系列则更适合由工具自动生成。一个文法是 LL(1) 当且仅当其预测分析表无冲突；一个文法是 LR(k) 当且仅当其 LR 分析表无冲突。

**算符优先文法** 是另一类自底向上分析方法，基于终结符之间的优先关系而非项集构造，本库未单独实现算符优先分析器，但其核心思想——终结符之间的优先关系——与 LR 分析中移进/归约的决策逻辑有相似之处。

### 语法制导翻译（SDT）

本库中的 AST 构建部分实现了语法制导翻译的概念：每个产生式在归约时执行一段**语义动作**，根据产生式的语义模式将子节点组装为 AST 节点。这通过 `GrammarAstBuilder.reduce_by_production` 实现：

- 对 ε 产生式，生成特殊的空标记节点
- 对单符号产生式（传递产生式），直接透传子节点
- 对二元运算模式（非终结符—运算符—非终结符），构造 BinaryExpr
- 对尾递归模式（如 `E → T + E`），通过继承属性平展左递归结构的 AST
- 对括号模式（`(` 非终结符 `)`），构造 ParenExpr
- 对一元前缀模式（运算符 非终结符），构造 UnaryExpr

这种设计使得语法分析和语义分析紧密耦合——在归约语法的同时就地构造语义结构，无需后处理遍历语法分析树。
